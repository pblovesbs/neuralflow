NEURALFLOW: ARCHITECTURE & SYSTEM OVERVIEW
==========================================

1. WHAT NEURALFLOW DOES
-----------------------
NeuralFlow is a local AI edge-agent orchestrator. It allows non-technical users to build, manage, and execute powerful AI pipelines and workflows entirely locally on their personal Mac devices. It removes the complexities of LLM management, file I/O operations, and graph logic by providing a polished, node-based visual interface.

2. FEATURES OFFERED
-------------------
- **Local AI Execution**: Bypasses cloud APIs entirely. All models run locally, ensuring total privacy and zero API costs.
- **Node-Based Visual Canvas**: Users build DAGs (Directed Acyclic Graphs) by connecting Trigger Nodes, Agent Nodes, and Action Nodes.
- **Hardware Optimization Wizard**: Automatically detects system specs (e.g., RAM) and uses subprocess shell commands to pull and install the most optimized local LLM (like qwen2.5:0.5b) via Ollama.
- **Frictionless Native Integration**: Includes features like native macOS file-picker modals (via AppleScript) instead of requiring manual file path entries.
- **Real-Time Streaming Logs**: Streams LLM token generation and system logs live to the UI as the workflow executes.
- **Cyclic Error Detection**: Automatically analyzes node structures to prevent infinite loops before execution.

3. HOW IT WORKS (SYSTEM ARCHITECTURE)
-------------------------------------
The system is divided into a "dumb" visual Frontend and a heavy-lifting execution Backend.

### Backend (Execution Engine)
Built with Python, FastAPI, and Pydantic, the backend is responsible for graph evaluation, hardware management, and AI execution.
- **API Routes (`backend/api/routes`)**: 
  - `execute.py`: Receives the JSON DAG payload from the frontend and triggers the execution flow.
  - `models.py`: Handles checking, pulling, and managing local LLMs via Ollama.
  - `system.py`: Manages hardware setup and OS-level operations.
  - `websocket.py`: Manages WebSocket connections for streaming real-time logs.
- **Core Logic (`backend/core`)**:
  - `executor.py`: The async executor. Takes the parsed DAG, resolves dependencies, and runs nodes sequentially or in parallel, passing context between them.
  - `graph_parser/`: Contains the Topological Sort algorithm to map out dependencies and detect infinite loops.
  - `ollama_client/` & `ollama_manager.py`: Connects async to the local Ollama instance (`http://127.0.0.1:11434`) to stream responses back in chunks.
  - `os_bridge.py` & `file_parser.py`: Handles native OS features (like file pickers) and parsing file text to be injected into prompts.

4. HOW THE UI IS CONNECTED TO IT
--------------------------------
### Frontend (Client Interface)
Built with Next.js (App Router), React 18, React Flow (`xyflow`), and Zustand. The UI holds no execution logic; it simply paints state and talks to the backend.
- **State Management (`frontend/src/store/flowStore.ts`)**: Zustand tracks every node movement, edge connection, and log update globally.
- **Components (`frontend/src/components/nodes`)**: Custom Trigger, Agent, and Action nodes that user interact with on the canvas.

### The Connection Pipeline (Deployment Process)
1. **Graph Serialization**: When "Deploy Workflow" is clicked, the UI serializes the visual React Flow nodes into a strict JSON DAG format.
2. **REST API Transport**: The Frontend sends this JSON payload via a `POST` request to the Backend's `execute.py` route.
3. **WebSocket Handshake**: Simultaneously, the Frontend opens a WebSocket connection to `websocket.py`.
4. **Execution & Streaming**: The Backend parses and executes the graph. As the local Ollama AI generates text or system events occur, the Backend streams these chunks through the WebSocket.
5. **UI Rendering**: The Frontend's `flowStore` catches these WebSocket messages and dynamically updates the terminal log panel, giving the user real-time visual feedback of the "AI typing" and file I/O operations.
